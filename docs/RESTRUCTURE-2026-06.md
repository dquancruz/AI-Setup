# Restructure — before vs. after (2026-06)

> **📜 Historical record.** The "after" state this document describes (`shared/` + `tools/claude/`) was itself later replaced by `registry/` in Fase 1 of [`docs/AI-SETUP-PLAN-v2.md`](AI-SETUP-PLAN-v2.md) (commit `25476d0`). It's kept for the design lesson it documents (don't version per-tool generated trees), which is still valid and was generalized into the current plan — not for its paths, which no longer exist.

A comparison of what changed when the repo was reorganized toward `shared/` + `tools/claude/`. Full context on why is in `plan.md` (note at the top) and in the commit history; this document is just the before/after snapshot.

## Motivation

The original request was to make the setup more universal as new AI tools appear, without losing the automation already built. A plan generated by Cursor was evaluated that proposed an architecture with codegen (`scripts/transformers/`, `package.json`, committed `tools/cursor/`, drift-check CI) and porting the 12 subagents to `~/.cursor/agents/`. That plan had factual errors (it claimed `block-secrets.sh` and `dependency-and-secrets-audit/SKILL.md` were missing, when they already existed) and contradicted a decision already documented in `docs/tool-compatibility.md`: subagents and hooks stay **intentionally** exclusive to Claude Code. A lighter version of the same goal was chosen instead.

## Why there's no `tools/cursor/`

With subagents and hooks staying Claude-only, and Cursor's rules generated on the fly (not committed), Cursor ends up with no artifact of its own worth versioning in this repo: everything it needs is already in `shared/` (skills, MCP, AGENTS.md) or is generated directly in the target repo. Creating an empty `tools/cursor/` folder just for symmetry with `tools/claude/` would have been an abstraction with no content. If a tool (Gemini CLI, Copilot, etc.) ever gains genuinely exclusive artifacts, it gets its own `tools/<name>/` following the same pattern.

## Cursor Rules: from committed to generated

**Before:** `per-repo/.cursor/rules/*.mdc` were written and maintained by hand, in parallel with `per-repo/.claude/rules/*.md`. They had already started to diverge — a real example found in `backend.md` vs `backend.mdc`:

```diff
- Validate all input with Zod (TS) or Pydantic (Python) — never trust external data without a schema.
+ Validate input with Zod (TS) or Pydantic (Python).
```

The `.mdc` was a shortened, outdated paraphrase of the `.md`, with nothing flagging it as stale.

**After:** `setup-repo.sh` generates `.cursor/rules/*.mdc` on every run from `tools/claude/per-repo/rules/*.md` (single source), via the `generate_cursor_rule()` bash function:
- `paths:` → `globs:` (same value)
- adds `description:` (taken from the `.md`'s first `# Heading`)
- adds `alwaysApply: false`
- the body is copied **verbatim**, never summarized

No `.mdc` is ever committed to this repo — it can never go stale because it doesn't exist as a standalone file until `setup-repo.sh` writes it into the target repo. Verified: the generated body is byte-for-byte identical to the source `.md`, and re-running the script overwrites cleanly (no duplicates).

## What was dropped from the original Cursor plan

| Cursor's proposal | Decision | Reason |
|---|---|---|
| Port the 12 agents to `~/.cursor/agents/` (`agent-to-cursor.js`) | Dropped | Contradicts `docs/tool-compatibility.md`, which already declares agents "intentionally" exclusive to Claude Code |
| `scripts/transformers/` + `package.json` + `gray-matter` | Dropped | Over-engineering for 5 rule files; a ~15-line bash function is enough |
| Commit a generated `tools/cursor/` + drift-check CI | Dropped | Unnecessary if it's generated on the spot — this eliminates the possibility of drift instead of detecting it after the fact |
| `hooks-to-cursor.js` / `.cursor/hooks.json` | Dropped | Hooks stay Claude-only (already decided) |
| Implement `block-secrets.sh` and `dependency-and-secrets-audit/SKILL.md` "because they were missing" | Dropped | They already existed in the repo — the Cursor plan had that premise wrong |
| Rename `global/` → `tools/claude/global/`, `per-repo/` → a per-tool structure | **Adopted** | This is the part of the plan that did have merit, executed in a simpler version (without `tools/cursor/`) |

## Scripts modified

- **`install.sh`** — same 3 sections (verify `~/.claude`, backup, install), updated paths: `tools/claude/global/agents/` and `shared/skills/`.
- **`setup-repo.sh`** — same copy sections, paths updated to `shared/` and `tools/claude/per-repo/`; the `generate_cursor_rule()` function was added along with the step that replaces the old `cp .../.cursor/rules/*.mdc`.
