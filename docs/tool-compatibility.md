# Cross-Tool Compatibility

This repo is designed so that **Claude Code, Cursor, GitHub Copilot, Antigravity, and Codex** can all work on the same project with the same context. But not every layer "activates" the same way in every tool — this document explains exactly what each one gets when you clone the repo and run `setup-repo.sh`.

**General rule:** anything that lives in standard files (instructions, MCP, skills, rules) is portable. Anything that's an *internal mechanism* of Claude Code (hooks, subagents) has no 1:1 equivalent in the others — its knowledge does travel (via AGENTS.md/skills), but the orchestrator doesn't.

## What this means in practice

### If someone clones the repo and opens **Cursor**
It reads `AGENTS.md` automatically (same conventions, commands, architecture). It connects the same MCP servers via `.cursor/mcp.json`. Its `.cursor/rules/*.mdc` activate by path just like in Claude Code. As of the check on 2026-08-24 (see the verification log above), skills **do auto-trigger**: Cursor reads `~/.claude/skills/` directly (the same directory `install.sh` already populates — no adapter needed), with the same progressive-disclosure model Claude Code uses. It also has a bridged equivalent of the secret-blocking hook via `.cursor/hooks.json` (`hook-to-cursor.sh`), verified against the schema but not hands-on tested inside a live Cursor session — see `tools/cursor/capabilities.yaml`'s `hooks.known_gaps`. It still doesn't have the 13 subagents; the equivalent work is done by a single Cursor session reading the same context (its Custom Modes give per-agent context, but invocation is manual, not automatic parallel dispatch).

### If someone uses **Codex** or **Antigravity**
Instructions and MCP work natively for both. Rules work if the tool reads them as additional context (via AGENTS.md or a manual reference), without Claude Code's automatic progressive disclosure. Skills: Codex CLI gained native `SKILL.md` support around December 2025 (see the verification log's lower-confidence entry) but this repo doesn't render anything into Codex's discovery path yet — no `tools/codex/` adapter exists (Fase 5 territory). Antigravity's skills/rules support hasn't been independently re-verified this Fase; treat its row as inherited, not confirmed.

### If someone uses **GitHub Copilot**
The most limited of the five: it reads `copilot-instructions.md` (a symlink to AGENTS.md), and MCP only partially depending on the client (VS Code vs. others). It has no concept of skills or rules — anything it needs must be summarized inside AGENTS.md.

### What's (still) exclusive to **Claude Code**
- **Hooks that block BEFORE a write lands on disk with zero setup** — Claude Code's `PreToolUse` is native; Cursor's equivalent (`.cursor/hooks.json`'s generic `preToolUse`) needs the bridge this repo generates and, per the verification log, hasn't been confirmed working end-to-end inside a real Cursor session yet.
- **The 13 subagents** working in parallel with isolated context each (`solutions-expert`, `backend-expert`, `security-expert`, etc.) and automatic, no-mention-needed skill dispatch during that parallel work — Cursor's skills now auto-trigger too, but from a single session, not N parallel isolated-context ones.

This is intentional: Claude Code remains this setup's "full" tool. The others get progressively more of the project's **context and knowledge** as their own native support catches up — Cursor now gets most of it — but not the **orchestrator**.

## Practical implication for the team

- **Real parallel/multi-agent work** → use Claude Code.
- **Fast editing with the same project context** → Cursor, Codex, or Antigravity work well; the repo already gives them AGENTS.md + MCP + rules.
- **Copilot** → treat it as the minimum-viable case; if a convention is critical, it must be explicit in AGENTS.md, not assumed from a skill or a hook.
- If a skill turns out to be critical for **any** tool to follow (not just Claude Code), consider promoting it to a short section inside `AGENTS.md` instead of leaving it as a skill only — that way it doesn't depend on auto-discovery.
