# Contributing

The golden rule of this repo: **edit `registry/`, never the generated output.**

`registry/` is the single source of truth (SSOT) — agents, skills, rules, hooks,
scripts, and templates all live there once. Everything else is a rendering of
it for a specific tool or a specific target repo:

- `plugins/` and `.claude-plugin/marketplace.json` are generated by
  `tools/claude/build-plugins.sh` from `registry/agents/`, `registry/skills/`,
  and `registry/packs.yaml`. CI fails if they're out of sync with what that
  script would produce — run it and commit its output after touching any of
  those three inputs.
- `.cursor/rules/*.mdc`, `.cursor/hooks.json`, `.cursor/hooks/_bridge.sh`, and
  `.github/copilot-instructions.md` inside a *target* repo are rendered by
  `setup-repo.sh` from `registry/rules/`, `registry/hooks/`, and
  `tools/claude/settings.json` — never hand-edit those in a repo that ran
  `setup-repo.sh`, they're overwritten on the next run.
- `~/.claude/agents/` and `~/.claude/skills/` (global install) come from
  `install.sh` (deprecated) or `/plugin install <pack>@ai-setup`, both
  sourced from `registry/`.

If you find yourself editing a file under `plugins/`, `.cursor/`, or a
generated `.github/copilot-instructions.md` directly, stop — the fix belongs
in `registry/` (or in the adapter script that renders it), or the next
`setup-repo.sh`/`build-plugins.sh` run will silently discard your change.

## Making a change

1. Edit the relevant file(s) under `registry/` (or the adapter under `tools/`
   that renders them).
2. Regenerate anything derived: `tools/claude/build-plugins.sh` if you
   touched agents/skills/packs; re-run `setup-repo.sh` in a scratch repo to
   sanity-check rule/hook rendering if you touched `registry/rules/` or
   `registry/hooks/`.
3. Run the test suite: `npm test` (bats smoke tests + frontmatter lint).
4. One commit per logical change, Conventional Commits
   (`feat: …`, `fix: …`, `docs: …`), in English or Spanish matching whatever
   the surrounding history in that file already uses.
5. Never delete something outright — move it to `docs/archive/` with a short
   note explaining why it was retired (see any file already there for the
   pattern). This repo's own history has to stay legible to whoever's
   debugging a regression a year from now.
6. If a change needs a product decision this file (or `README.md`/`USAGE.md`)
   doesn't already settle, ask — don't guess and ship it.

See `docs/AI-SETUP-PLAN-v2.md` and `update-plan-aug-2026.md` for the active
roadmap and the reasoning behind past architectural decisions.
