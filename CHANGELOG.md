# Changelog

History of `AI-Setup` itself (formerly `claude-automation-setup`) — how this tooling repo evolved. This is not the per-repo `CHANGELOG.md` that `semantic-versioning` generates for projects that *use* this setup; it's the story of the setup itself.

No version tags exist yet (this repo isn't published/versioned independently), so entries are grouped by milestone rather than SemVer release.

## 2026-08-24 — Fase 2 of `update-plan-aug-2026.md`: no more symlinks, and a real Copilot-instructions bug fixed along the way

- **Eliminated every symlink in the setup, not just the fragile Windows case**: `CLAUDE.md` and `GEMINI.md` are now real one-line files (`@AGENTS.md`) — both Claude Code and Gemini CLI support this native import syntax (verified against their own docs, 2026-08-24), so there's no symlink, and no Windows-without-Developer-Mode fallback branch needed at all. The plan reserved keeping a symlink for `GEMINI.md` if Gemini didn't support imports; it does, so the result is zero symlinks anywhere in the repo. `.cursor/mcp.json` is now a real copy of `.mcp.json` (Cursor reads that exact path, not a root `.mcp.json` — also verified), regenerated on every `setup-repo.sh` run so it can't drift.
- **Found and fixed a real, previously-undetected bug while retiring `setup-portability.sh`**: that script symlinked `.github/copilot-instructions.md` straight to `AGENTS.md`, silently bypassing the condensed, line-budget-capped rendering `lib/condense.mjs`/`tools/copilot/enable.sh` already existed to produce — `setup-repo.sh` never actually called that adapter. Any repo following `USAGE.md` as written got an uncondensed Copilot file despite the condensation infrastructure working correctly in isolation. Fixed: `setup-repo.sh` now calls `tools/copilot/enable.sh --scope=repo` directly (degrades to a warning, not a hard failure, if `node` isn't on PATH).
- Retired `setup-portability.sh` and the manual "Cross-tool portability" step entirely — `setup-repo.sh` does all of it in one pass now. The old script is kept at `docs/archive/setup-portability.sh` with a header explaining why, as a historical record only.
- Added a `windows-latest` job to `.github/workflows/ci.yml`'s `fixture-install` matrix — the Fase 0 CI never actually ran on Windows, which made "no more Windows symlink fallback" impossible to verify in CI. First real Windows CI run for this repo.
- `test/setup-repo.bats` grew 4 tests (no symlinks anywhere in a freshly set-up repo, no `ln -s` left in any active script, exact `CLAUDE.md`/`GEMINI.md` content, `.github/copilot-instructions.md` is actually condensed and not a verbatim `AGENTS.md` copy) — 22 bats tests total, all green, plus a clean `shellcheck` pass on all 11 active `.sh` files.

## 2026-08-24 — Fase 1 of `update-plan-aug-2026.md`: real Cursor hooks + corrected skills/hooks portability

- **Cursor hooks are real now, not "no equivalent"**: added `tools/cursor/adapt/hook-to-cursor.sh` + `tools/cursor/adapt/hook-bridge.sh`, wired into `setup-repo.sh` and `tools/cursor/enable.sh`. Generates `.cursor/hooks.json` (schema v1) + `.cursor/hooks/_bridge.sh` in every repo `setup-repo.sh` touches, bridging the existing `.claude/hooks/*.sh` scripts (unchanged, still the single source of truth) into Cursor's `preToolUse`/`postToolUse` contract — matchers read from `tools/claude/settings.json`, `failClosed` defaults to `true` for pre-tool-use (security) hooks and `false` for post-tool-use (feedback) ones. Verified end-to-end locally against real payloads (blocks an AWS key and a real `.env` write, allows clean writes) — see `test/cursor-hooks.bats` (7 new tests). Deviates from the plan's own suggested event mapping (granular `beforeShellExecution`/`afterFileEdit`) after checking `cursor.com/docs/hooks` directly: neither hook actually matches shell/MCP calls, and Cursor has no granular pre-write-blocking event at all — only the generic `preToolUse` can block a `Write` before it lands on disk.
- **Cursor's Skills support was stale in this repo's own docs**: re-verified against `cursor.com/docs/skills` and found Cursor now natively auto-discovers `SKILL.md` (progressive disclosure, same model as Claude Code) and — notably — reads `.claude/skills/`/`~/.claude/skills/` directly for compatibility, meaning the skills `install.sh` already installs are visible in Cursor today with zero adapter work. Corrected the README portability table, `docs/tool-compatibility.md`, and `tools/cursor/capabilities.yaml` from "🟡 referenced, path only" to "✅ native". Also checked Codex CLI (lower confidence — secondary sources only): gained native `SKILL.md` support around December 2025, corrected from ❌ to 🟡 (support exists, this repo doesn't render into it).
- Added `docs/tool-compatibility.md`'s `## Verification log` — the compatibility table had zero verification dates before this Fase (see `docs/AUDIT-v3.md`); this adds dated, sourced entries for what Fase 1 actually re-checked and explicitly flags what wasn't re-verified this pass, instead of dating the whole table without having checked it.

## 2026-08-24 — Fase 0 of `update-plan-aug-2026.md`: baseline (audit, smoke tests, CI)

- Added `docs/AUDIT-v3.md`: full inventory of the 13 agents / 12 skills (size, tier/Essence completeness, stack-coupling per agent, triggering-convention check per skill), a script-vs-README destination audit, and a `capabilities.yaml`-vs-README consistency check (internally consistent; flags the Cursor-hooks claim as likely stale, to be fixed with a live source check in Fase 1).
- Added a real smoke-test net where there was none: `test/install.bats` (4 tests) and `test/setup-repo.bats` (9 tests) run `install.sh`/`setup-repo.sh` against throwaway `HOME`/target-repo fixtures and assert every README-declared destination, idempotency (double-run produces an identical tree hash), and non-overwrite of `.mcp.json`/`.claude/settings.json`/`.env.local`/`.local-docs/` plus `AGENTS.md`'s append-only patch behavior. `test/lint-frontmatter.mjs` validates every `SKILL.md`'s `name`/`description` frontmatter. `bats` added as an npm devDependency (`package.json`, new — dev-only, doesn't affect what `install.sh`/`setup-repo.sh` put in target repos).
- Added `.github/workflows/ci.yml` — this repo's own CI (distinct from `registry/templates/github/workflows/*`, which render into target repos): `shellcheck` over every `.sh`, `npm test`, and an `install.sh` + `setup-repo.sh` fixture run matrixed on `ubuntu-latest`/`macos-latest` with an idempotency re-check.
- Fixed the shellcheck findings that surfaced from actually running it (SC2086 unquoted var, SC2012 `ls | wc -l`, SC2129 repeated redirects, SC2088 literal `~` in doc-text echoes — all style/info, no behavior change) in `install.sh`, `setup-repo.sh`, `tools/cursor/enable.sh`.
- Added `.gitattributes` forcing LF on `.sh`/`.bats`/`.mjs`/`.js` — the stored blobs were already LF-only, but `core.autocrlf=true` on Windows checkouts was rendering them as CRLF on disk, which both breaks a script's shebang if ever re-saved that way and makes `shellcheck` flag every line with a spurious `SC1017`.

## 2026-08-13 — Renamed to AI-Setup; local docs, plain commit/PR convention, descriptive CHANGELOG

- Renamed the repo (local folder, GitHub remote, and every internal reference) from `claude-automation-setup` to `AI-Setup`. Historical/point-in-time docs (`plan.md`, the "Nivel 3" docs, restructure analysis) were deliberately left referencing the old name — they're a record of what was true when written.
- Commit/PR convention: PR titles are now plain by default (no emoji) — matches the convention commits already followed. Emoji is an explicit opt-in exception for a project's initial bootstrap phase only, toggled via a new `Commit/PR style:` line in `AGENTS.md`. Updated `pr-formatter`, `auto-pr`, `pr-manager`, and `auto-pr.js`'s examples accordingly.
- Added `.local-docs/`: a new gitignored, per-repo folder for human-context notes that must never reach the remote — `plan.md` (the living working plan, phases/tasks/status), `architecture.md`, `security-gaps.md`, and `decisions.md`. Backed by a new `local-docs` skill (agent count unchanged at 13; skill roster now includes `local-docs` and drops the never-implemented `dependency-and-secrets-audit` phantom entry, real skill count still 12). `security-expert`, `solutions-expert`, and `agent-orchestrator` are wired to keep it current — e.g. a fixed security gap gets marked `Done` with the approach taken, not left stale. `setup-repo.sh` scaffolds it (create-if-missing) and gitignores it.
- CHANGELOG generation moved to a Keep-a-Changelog `[Unreleased]` scaffold with entries sourced from the merged PR's own title + `## Why` section (description, PR link, Jira keys) instead of a raw commit-message dump — see `on-merge.yml`, `documentation-generator`, and `semantic-versioning`.
- Upgrade path for repos already running this setup: re-running `setup-repo.sh` now patches an existing `AGENTS.md` with any new required lines (append-only, existing content untouched) instead of only skipping it — documented in `USAGE.md`'s new "Upgrading an existing repo" section.
